>
> 规则：每一条都必须能「手动测一次，看出过没过」。写不出测法的，不是标准，是愿望。

## 一、给谁用

- 用户：我们班同学，加上隔壁宿舍，**不超过 50 人**
- 他们在哪问：班级群、宿舍楼下、半夜十一点
- 现在怎么解决：问十个人，或者自己翻学生手册第 40 页

## 二、他们会问什么（真实问过的，不是我编的）

| 问题 | 现在怎么办 | 我希望它怎么答 |
|---|---|---|
| 一卡通丢了去哪补办 | 群里问，等 20 分钟 | 直接说地点、工本费、要不要带学生证 |
| 转专业什么时候能申请 | 翻手册，翻不到 | 给日期区间和条件 |
| 补考没过怎么办 | 问学长，说法不一 | 说清流程 |
| 图书馆明天几点关门 | 走到门口看牌子 | 给时间，加出处 |

## 三、答错会怎样

| 错法 | 后果 | 严重程度 |
|---|---|---|
| 编一个时间/金额 | 有人白跑一趟，或者交错钱 | 高 |
| 答成别的学校的规定 | 信任直接崩，没人再用 | 高 |
| 不给出处 | 没法核对，等于没说 | 中 |
| 答得太长 | 群里没人看完 | 低 |

## 四、什么叫做完（第一版写的，v0.2 起在这张单子上往上加）

- [ ] `python -m agent "问题"` 能跑，不需要装额外的包
- [ ] 回答里出现**出处**（`[...]` 这种标记），不是光一段话
- [ ] 资料里没写的，它说「资料里没写」，**不瞎猜**
- [ ] 每次调用都在 `logs/run.jsonl` 留一行，含 token 数和耗时
- [ ] 换一个问题不用改代码
- [ ] `python -m unittest` 全绿

## 五、这一版明确不做

- 不做网页界面（CLI 就够，先用一周再说）
- 不做多轮对话（第二幕才做，现在一问一答）
- 不做用户系统（就我们班，不登录）
- 不做知识库管理后台（资料我手动抄进 `data/docs.json`）
