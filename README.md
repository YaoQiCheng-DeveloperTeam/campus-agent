# campus-agent

[![check](https://github.com/YaoQiCheng-DeveloperTeam/campus-agent/actions/workflows/check.yml/badge.svg)](https://github.com/YaoQiCheng-DeveloperTeam/campus-agent/actions/workflows/check.yml)

「灯塔计划」那门课里，学生要亲手做出来的那个项目：一个班级群里能用的校园助手。
问它图书馆几点关门、一卡通丢了去哪补办、空调坏了找谁，它答得上来，而且给出处。

这个仓库按**版本**切成文件夹。一个文件夹 = 一个能直接跑起来的完整程序。

```
v0.1/    第 1 幕结束时它长的样子
v0.2/    第 2 幕结束时它长的样子
...
v1.2/    结业时它长的样子
```

---

## 我该从哪进

| 你是 | 怎么做 |
|---|---|
| 学生，跟着课做 | 先 fork 本仓库，然后 `cd v0.1`，那就是你的起点。后面每一幕照课程改自己那份，不用来这抄 |
| 学生，只想看看它长什么样 | `cd v0.1 && python -m agent "一卡通丢了去哪补办"`，不用装依赖 |
| 想对比两个版本差在哪 | 直接看 GitHub 的 `compare/v0.1...v0.2`，或者 `diff -r v0.1 v0.2` |
| 维护课程的人 | 看下面的「维护约定」和 [CHANGELOG.md](CHANGELOG.md) |

跑起来只要三条命令（Python 3.10+，不需要 `pip install`）：

```bash
cd v0.1
python -m agent "一卡通丢了去哪补办"
python tools/check.py          # 6 条验收
```

## 为什么一版一个文件夹，而不是一个个分支 / tag

因为**读的人是大一新生**。

- 分支和 tag 要先懂 git，再 `git switch`，还得处理「我改过工作区所以切不过去」。
  文件夹不用：点进去就是那一版，浏览器里能直接看代码。
- 课上讲某一行代码时，链接是 `v0.3/agent/context.py#L42`，学生点开就看到，
  不用先 checkout。
- 学生把仓库下成一个 zip 也有全部版本，断网也能对照。

代价是同一份 `data/docs.json` 会在十二个文件夹里各存一份。这是故意的：
**每一版必须自包含**——单独拿走 `v0.5/` 也能跑，不需要别的目录配合。
判分、演示、面试都用得上这一点。

## 每一版里有什么

```
v0.1/
├── SPEC.md          验收标准（学生自己写的，改需求先改它）
├── README.md        这一版怎么跑、三种模型后端
├── agent/
│   ├── main.py      入口：拼 messages → 调模型 → 打印 → 记日志
│   ├── llm.py       三种后端 + token 计数
│   └── knowledge.py 资料怎么找（v0.1 还是字面重合）
├── data/
│   ├── docs.json    校内资料 37 条，day = 第几天抄进来的
│   ├── history.json 群里问过的问题
│   └── rules.md     系统规则，模型看的就是这个文件
├── tests/           单测，不联网也能跑
├── tools/
│   ├── check.py     这一版的验收，一键跑
│   ├── reader.py    看清一段代码的结构
│   └── review.py    审别人提的 diff
└── logs/            （跑起来才生成，不进仓库）
```

三种模型后端，按顺序找，找到哪个用哪个：

| 后端 | 怎么开 | 说明 |
|---|---|---|
| 平台网关 | `export AGENT_GATEWAY=...` | 课程内用，不用自己买 key |
| 任意 OpenAI 兼容 | `export OPENAI_API_KEY=sk-...` | 也支持 `OPENAI_BASE_URL` / `AGENT_MODEL` |
| 离线占位 | 什么都不配 | **不是模型回答**，只把最像的资料原文贴出来 |

仓库里没有任何密钥，也不会有。

## 维护约定

给后面接手的人：

1. **老版本只修 bug，不加油。** 想加功能就开新文件夹。
   想改 `v0.1` 的答案措辞，先问一句「课上讲到它了吗」——讲到才改，否则学生会发现仓库和视频对不上。
2. **每版自包含。** 禁止 `../` 引用别的版本，禁止共享 `data/`。
3. **加一个版本的流程**：
   - `cp -r v0.2 v0.3`，再改；
   - 跑 `python tools/check.py` + `python -m unittest discover -s tests`；
   - 在 [CHANGELOG.md](CHANGELOG.md) 写一节：改了什么、对应课程哪几节、怎么验收、已知问题；
   - 更新根 README 的版本表状态；
   - 课程站点的 `starter/campus-agent` 由课程仓库的 `npm run sync:agent` 从本仓库同步，**不要两边各改一份**。
4. **数据只有一个来源。** `data/docs.json` 由课程仓库的 `server/proj/seed.py` 导出，
   改资料去改 seed，不要手改 JSON。
5. **每个 `v*/` 都得能跑。** CI 会对每个版本跑一遍 `tools/check.py` + 单测
   （`.github/workflows/check.yml`），红了别合并。加一版不用改 CI，目录名对得上就会被扫到。
6. 提交信息写「v0.3: 加了什么」，不要写「update」。
